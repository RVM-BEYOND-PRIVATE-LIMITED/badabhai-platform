# BadaBhai Worker App (Flutter)

Phase 1 **scaffold** of the chat-first worker app. Intentionally lightweight: no
heavy UI, no extra pub dependencies, and the API client returns mock data so the
flow runs end-to-end before the backend is wired.

## Flow / screens

`Splash → PhoneLogin → OtpVerify → SetPin → Consent → Name → ResumeUpload →
ChatProfiling → (VoiceNote) → ProfilePreview → Finishing | TradeForm →
Building → Resume`

`ResumeUpload` (#1499) is the two-door step: upload a résumé, or say there is
no résumé. The "no résumé" door is the handover `Name` made directly before
that screen existed — same route, same request sequence, pinned by a test.

### Consent (DPDP)

- `Consent` shows two approved notices — employer sharing
  (`docs/product/employer-sharing-consent-notice.md`) and voice
  (`docs/product/voice-consent-notice.DRAFT.md`) — under ONE "I agree" tick,
  which grants `profiling`, `resume_generation`, `voice_processing`,
  `employer_sharing`, `employer_messaging` at `kConsentVersion` (`2026-11-04`).
- Existing workers whose consent predates that notice get a one-time
  full-screen prompt (`/employer-sharing`) from the home shell: "Haan,
  dikhayein" → `POST /consent/employer-contact/grant`; "Abhi nahi" is
  remembered on the device per worker + notice version.
- Settings → "Companies ko profile dikhayein" turns it OFF (confirm +
  withdraw) or back ON (through the same prompt). The server is the authority
  on every one of these; the client only shows the notice and asks.

## Run (requires the Flutter SDK)

```bash
cd apps/worker-app
flutter pub get
flutter analyze
flutter test
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3001   # Android emulator -> host
```

> ⚠️ Flutter may not be installed on every dev machine. The Dart sources are
> written to pass `flutter analyze` with `flutter_lints`; install the Flutter SDK
> to build/run locally.
>
> **CI:** `flutter analyze` + `flutter test` are a **blocking** gate
> ([`.github/workflows/worker-app.yml`](../../.github/workflows/worker-app.yml)),
> pinned to Flutter **3.27.4**, running on every PR that touches `apps/worker-app`.
> A red check blocks merge — so CI is the source of truth even if you can't run
> Flutter locally.
>
> The platform runner folders (`android/`, `ios/`, `web/`, etc.) are generated by
> `flutter create .` in this directory — run it once after installing the SDK.
